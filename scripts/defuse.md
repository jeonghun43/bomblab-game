## 커리큘럼

|---|---|---|---|---|---|---|---|

### 설계 원칙 (대본을 고칠 때 지킬 것)
1. **현상 먼저, 이름은 나중에.** 새 용어는 그 현상을 보여 준 다음 대사에서 `[[용어]]`로 처음 등장시킨다.
2. **한 장면에 새 단어 하나.** `lea`, 스택, 32비트 레지스터 이름은 튜토리얼에서 먼저 꺼내지 않는다. `%esi`/`%eax`는 마주쳤을 때 "rsi/rax의 다른 이름"으로만 설명한다.
3. **도구는 필요해진 순간에.** `도구:` 항목으로 과제마다 하나씩 연다. 안 배운 명령은 게임이 막는다.
4. **예측 → 확인.** `##### 예측` 다음 과제에서 직접 실행해 확인하게 한다.
5. **도움은 점점 줄인다.** 앞 레슨은 `예시:`(입력칸의 흐린 글씨)를 주고, final 레슨의 뒷부분은 `목표:`만 준다.
6. **연습에서는 벌점 없음.** `벌점: 예`는 final 레슨에만 둔다.

## 말투

반장은 신입에게 반말 구어체로 말한다. **"~다.", "~한다."로 끝내지 않는다.** (사용자가 고른 종결어미, 2026-10-01)

| 상황 | 쓰는 말투 | 예 |
|---|---|---|
| 설명할 때 | ~하는 거야 / ~인 거지, ~하거든 / ~잖아, ~란 말이지 / ~라고, ~해 / ~이야 | "이 칸들을 레지스터라고 부르는 거야." "여기가 서버실이야." |
| 시킬 때 | ~해 보자 / ~하자, ~해 볼래?, ~하면 돼 | "아무거나 쳐 볼래?" |
| 물어볼 때 | 신입, 너 생각은 어때?, ~일까? / ~인 것 같아? | "신입, 너 생각은 어때? rax는 몇이 될 것 같아?" |
| 반응할 때 | 좋아, 잘했어! / 거봐, 내가 뭐랬어 / 괜찮아, 다시 해 보자 | "괜찮아, 다시 해 보자." |

- **한 가지 어미를 몰아 쓰지 않는다.** 특히 "~거든"은 한 대사에 한 번까지만 쓰고, 연달아 나오면 "~해 / ~이야"로 바꾼다. (사용자가 "~거든만 계속 나와서 이상하다"며 "~해 / ~이야"를 추가, 2026-10-01)
- 쓰지 않는 것: "~해 봐", "알겠지? / 맞지?", "~할 수 있겠어?", "오, 제법인데?"
- `목표:`는 "~하자", `힌트:`는 "~하면 돼"로 끝낸다.
- `##### 확인:` 버튼은 신입이 반장에게 하는 말이라 존댓말로 쓴다("멈췄어요!").
- 내레이션은 쓰지 않고 반장이 직접 말하게 한다.

## 용어

> 대사 속 `[[용어]]`를 누르면 뜨는 풀이. 반장 말투로 쓴다.

- 프로그램: 컴퓨터가 할 일을 순서대로 적어 둔 목록인 거야. 폭탄도 프로그램이거든.
- 명령: 프로그램의 한 줄인 거야. CPU가 한 번에 하는 아주 작은 일 하나(넣기, 더하기, 비교하기…)거든.
- 기계어: CPU가 직접 읽는 숫자로 된 명령인 거야. 사람은 읽기 어렵거든.
- 어셈블리: 기계어를 사람이 읽을 수 있게 짧은 영어 단어로 옮긴 거야. mov, add, call 같은 단어가 나오잖아.
- gdb: 실행 중인 프로그램을 멈추고, 한 줄씩 움직이고, 속을 들여다보는 도구인 거야. 이런 걸 디버거라고 부르거든.
- breakpoint: "여기 오면 멈춰"라고 꽂아 두는 표시인 거지. gdb에서는 break 명령으로 거는 거야.
- 레지스터: CPU 안에 있는 아주 작고 빠른 칸인 거야. rax, rdi, rsi처럼 이름이 붙어 있고, CPU는 여기에 숫자를 넣어서 계산하거든.
- 메모리: 프로그램이 쓰는 커다란 창고인 거야. 칸이 아주 많아서 칸마다 번호가 붙어 있거든.
- 주소: 메모리 칸의 번호, 그러니까 사물함 번호 같은 거지. 보통 0x로 시작하는 16진수로 쓰거든.
- 16진수: 0x로 시작하는 숫자 표기법인 거야. 0x9 다음이 0xa, 0xf 다음이 0x10(=16)이거든. 주소 쓸 때 주로 쓰는 거지.
- 문자열: 글자들을 한 줄로 이어 놓은 거야. 메모리에 한 글자씩 차례로 들어 있거든.
- 함수: 이름이 붙은 명령 묶음인 거야. 일을 대신 해 주는 심부름꾼이라고 생각하면 돼. phase_1, strings_not_equal 같은 게 함수 이름이거든.
- 인자: 함수한테 일을 시킬 때 넘겨주는 재료인 거야. 1번째는 rdi, 2번째는 rsi 칸에 넣어서 보내거든.
- 반환값: 함수가 일을 마치고 돌려주는 결과인 거지. rax 칸에 담겨서 돌아오거든.
- 디스어셈블: 프로그램의 기계어를 어셈블리로 풀어서 보여 주는 거야. gdb에서는 disas 명령이거든.

## 해독기 풀이

> 해독기에서 읽히는 단어를 누르면 나오는 설명. 키는 decoder.js의 토큰 표에 맞춘다.

- addr: 이 명령이 놓인 번지인 거야. 폭탄은 위 줄부터 아래로 차례대로 실행하거든. <+4>는 함수 시작에서 4칸 떨어졌다는 뜻이고.
- prep: 함수의 준비 운동이랑 정리 운동인 거야. 스택이라는 공간을 잠깐 빌렸다가 돌려주거든. 이건 다음 교육에서 자세히 배우자.
- ret: 심부름 끝! 나를 부른 곳으로 돌아가라는 거지.
- rsp: 레지스터인 거야. 스택 꼭대기가 어디인지 기억하는 칸이거든.
- mov: "넣어라"란 말이지. 왼쪽 값을 오른쪽 칸에 넣는 거야.
- mem: 숫자인데 크기가 딱 주소처럼 생겼잖아. 이 사물함에는 뭐가 들어 있을까?
- esi: rsi 칸의 다른 이름(아래쪽 절반)인 거야. 2번 주머니거든. 그러니까 0x402400이 두 번째 인자로 넘어가는 거지.
- call: "심부름 보내라"란 말이지. 오른쪽 이름의 함수가 일을 하고 돌아오는 거야.
- callAddr: 심부름꾼 함수가 사는 번지인 거야.
- sne: "문자열이 다른가?"를 알아보는 함수인 거야. 1번 주머니(rdi)랑 2번 주머니(rsi)의 문자열을 비교해서, 같으면 0, 다르면 1을 결과 주머니(eax)에 담아 오거든.
- eax: rax 칸의 다른 이름(아래쪽 절반)인 거야. 심부름꾼이 결과를 담아 오는 결과 주머니거든.
- test: eax가 0인지 검사하는 거야.
- je: 방금 검사한 값이 0이면 오른쪽 번지로 점프하는 거지. 그러니까 explode_bomb 줄을 건너뛰는 거라고.
- jt: 점프할 목적지인 거야. explode_bomb 바로 다음 줄이거든.
- boom: 폭발. 이 줄에 닿으면 끝인 거야. …그럼 이 줄을 건너뛰는 방법이 어딘가 있다는 뜻일까?

정답: 거봐, 내가 뭐랬어. 1번 주머니 rdi에는 네 입력의 주소, 2번 주머니 rsi에는 0x402400이 들어가는 거야. 심부름꾼은 두 사물함의 글자를 비교하는 거지.
오답: 괜찮아, 다시 해 보자. esi는 rsi의 다른 이름이거든. rsi는 2번 주머니잖아. 1번 주머니 rdi에는 네 입력의 주소가, 2번 주머니에는 0x402400이 들어가는 거야.
